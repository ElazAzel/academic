Применяй чеклист OWASP Top 10:2025 (A01–A10) к представленным изменениям. Полный
чеклист — в reference `owasp-top10` (`docs/owasp-top10-2025.md`) и в скилле
`owasp-top10-2025`. Проверяй по каждой затронутой категории:

- **A01 Broken Access Control**: явная проверка прав на каждом действии, нет IDOR,
  RLS включён и покрывает все операции, клиентские проверки — только UX.
- **A02 Security Misconfiguration**: CSP/заголовки, cookies HttpOnly/Secure/SameSite,
  нет дефолтных кредов/debug в проде, `service_role` только на сервере.
- **A03 Software Supply Chain**: зависимости минимальны, lockfile закоммичен,
  `npm audit` чист, нет скриптов из непроверенных источников.
- **A04 Cryptographic Failures**: секреты только в env, нет хардкода, пароли через
  провайдера (argon2id), чувствительное по HTTPS.
- **A05 Injection**: только параметризованные запросы (Prisma), нет
  `dangerouslySetInnerHTML`/ `javascript:` href, серверная Zod-валидация ввода.
- **A06 Insecure Design**: лимиты/квоты на мутирующих операциях, границы доверия для
  приглашений/шеринга/восстановления доступа.
- **A07 Authentication Failures**: истечение/инвалидация сессий, единая точка проверки
  auth, одноразовые коды с коротким TTL.
- **A08 Software or Data Integrity**: валидация внешних данных (webhook/CSV) по схеме,
  проверка подписи webhook.
- **A09 Security Logging**: значимые события логируются без PII и секретов.
- **A10 Mishandling of Exceptional Conditions**: явная обработка ошибок, fail securely,
  пользователю — безопасное сообщение без внутренностей.

Возвращай: список найденных проблем с категорией (A01–A10), местом в коде и планом
исправления; если чисто — кратко подтверди и укажи, какие категории проверены.
